A take-home map of the Hackwise proof of concept — the core flow, the files, and one pattern worth reusing.

The core flow

No key configured? server.mjs short-circuits to a labeled demo brief instead of the Gemini call — the flow still runs end to end.

The files

server.mjsZero-dependency Node HTTP server. Serves public/ and handles POST /api/analyze. Loads .env.local, keeps the API key server-side, maps errors to codes.
public/index.htmlThe whole landing page — every section, inline CSS design tokens, the dark result panel. Ported 1:1 from design/.
public/app.jsThe UI brain: composer (Enter / Shift+Enter), URL validation, the reading animation, tab switching, rendering the brief, and copy-to-clipboard.
lib/extract.mjsFetches the URL (timeout + size cap) and reduces the HTML to plain text. Treats the page as untrusted data.
lib/gemini.mjsBuilds the prompt, calls Gemini (REST, or the official SDK if installed), retries once on bad JSON. Model comes from env.
lib/schema.mjsValidates the model's JSON into a safe Brief shape before anything is shown; also the shared URL check.
lib/demoBrief.mjsThe labeled sample brief returned in demo mode.

One pattern worth reusing

Treat anything an LLM reads from the outside world as untrusted input, and validate anything it returns before you trust it.
  • In → the fetched page text is wrapped and explicitly labeled "data, not instructions" in the prompt (lib/gemini.mjs), so a malicious page can't hijack the model.
  • Out → the model's reply is parsed and shape-checked (lib/schema.mjs) with a one-retry fallback, so malformed output becomes a clean error instead of a broken UI.
  • Honesty → missing facts are null/"unknown" and inferred advice is labeled — the model is never allowed to invent competition rules.
Next time you wire an agent or LLM to a tool or the web, keep this in/out boundary: constrain the input, schema-check the output.
